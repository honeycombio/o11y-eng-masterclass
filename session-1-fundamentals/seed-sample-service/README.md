# seed-sample-service

Backfills the `sample-service` Honeycomb dataset used in Masterclass 1's
"one dataset, three ways" demo, referenced in the slides as *Dataset:
sample-service (seeded traces included)*.

**Run this before the session, not during it.** It emits ~400 historical
checkout traces (`auth` → `inventory_check` → `payment` → `confirmation`)
spread over the last 4 hours, with a ~7% payment failure rate and a ~12%
slow-inventory subset, so there's a real distribution to query against
rather than a single flat spike.

## Pre-session setup

1. Start the local Collector (see [`../collector`](../collector)):

   ```bash
   HONEYCOMB_API_KEY=<your key> docker compose up -d
   ```

2. Seed the dataset:

   ```bash
   go run main.go
   ```

   Override `SEED_COUNT` (default 400) or `SEED_WINDOW` (default `4h`, any
   Go duration string) if you want more traces or a wider spread.

3. Confirm in Honeycomb: the `sample-service` dataset should show ~400
   traces across the configured window, with a visible error rate and a
   long tail of slow `inventory_check` spans.

## Live demo script

Query the same dataset three ways, per the slides:

1. **As a rate:** `COUNT`, grouped by nothing, visualized as a time series.
2. **As a filtered search:** `WHERE error = true`.
3. **As a trace waterfall:** click any event, expand to its full trace.

## Design notes

- Span timestamps are set explicitly (`trace.WithTimestamp`) rather than
  generated by sleeping in real time, so seeding ~400 traces takes well
  under a second.
- `error` is a literal boolean attribute on the root span (not just OTel
  span status) because the slide's filtered-search demo depends on
  `WHERE error = true` as a field, not a status code.
- Attributes are drawn from the same four categories as the rest of the
  session: identity (`user.id`, `user.type`), request/execution
  (`http.request.method`, `http.route`), outcome
  (`http.response.status_code`, `error`, `error.type`), and service/code
  context (`service.version`, `deployment.environment`).
- `user.type` (values `free`/`premium`/`enterprise`) matches the book's
  Chapter 6 naming (Table 6-15) and its example values, not the slide's
  original "customer.tier" wording — the slide was updated to match.
- HTTP attribute names follow the current stable OTel semantic conventions
  (`http.request.method`, `http.response.status_code`) via the `semconv`
  package, matching both the book (Chapter 6) and what `otelhttp` v0.69+
  emits automatically in `otel-quickstart` — checked directly against the
  book text and the `otelhttp` source, not assumed.
